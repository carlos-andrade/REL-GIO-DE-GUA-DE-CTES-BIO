# CARTA DE REGRAS DE SALVAMENTO — V1

**Projeto:** Relógio de Água de Ctesíbio
**Data de vigência:** 27/09/2026
**Repositório oficial:** carlos-andrade/RELOGIO_DE_AGUA_DE_CTESIBIO
**Status:** REGRA OPERACIONAL DO PROJETO

## 1. Regra fundamental

Todo conteúdo produzido nos chats deste projeto que tenha valor documental, técnico, histórico, arquitetural, experimental, de engenharia, de especificação, de teste ou de decisão deve ser registrado no repositório oficial.

O chat é o ambiente de trabalho. O GitHub é o registro oficial do projeto.

## 2. Proibição de armazenamento como fonte oficial no chat

Nenhum conteúdo produzido em um novo chat deve ser considerado o registro oficial do projeto.

A continuidade do projeto deve ocorrer pelo repositório, e não pela memória informal de chats anteriores.

Quando um novo chat precisar de contexto, a fonte prioritária será o conteúdo existente no repositório.

## 3. Salvamento obrigatório

Sempre que uma entrega gerar um artefato reutilizável, deve-se:
1. identificar o tipo de documento;
2. escolher a pasta correspondente;
3. criar ou atualizar o arquivo no repositório;
4. registrar data e versão;
5. preservar o histórico por commits;
6. confirmar o caminho do arquivo e o commit realizado.

## 4. Organização mínima

Os conteúdos devem ser classificados, conforme aplicável, em:
- GOVERNANCA/ — regras, cartas, políticas e controles;
- documentacao/prompts/ — prompts e instruções de projeto;
- documentacao/arquitetura/ — arquitetura e decisões estruturais;
- documentacao/especificacoes/ — requisitos e especificações;
- documentacao/testes/ — testes, critérios e resultados;
- documentacao/calibracao/ — calibração e metrologia;
- documentacao/historico/ — referências históricas;
- prototipos/ — projetos e protótipos;
- dados/ — dados e medições;
- anexos/ — materiais auxiliares.

Novas categorias podem ser criadas quando justificadas.

## 5. Integridade documental

Não sobrescrever conteúdo histórico sem necessidade.

Quando uma mudança representar evolução relevante, criar nova versão ou registrar claramente a alteração.

Preferir nomes versionados, por exemplo:
DOCUMENTO_V1.md
DOCUMENTO_V2.md

## 6. Rastreabilidade

Todo artefato importante deve conter, quando aplicável:
- nome do arquivo;
- projeto;
- finalidade;
- data de criação;
- versão;
- caminho no repositório;
- status;
- dependências ou referências;
- histórico de alterações.

## 7. Regra de confirmação

Após cada gravação no GitHub, informar:
- arquivo criado ou atualizado;
- caminho;
- versão;
- commit;
- status da operação.

Não declarar que algo foi salvo sem confirmação do GitHub.

## 8. Regra de continuidade

Em novos chats:
1. consultar o repositório antes de assumir contexto;
2. reutilizar os documentos existentes;
3. atualizar o repositório ao concluir uma entrega;
4. não transformar o conteúdo do chat em fonte oficial;
5. manter o Git como histórico auditável.

## 9. Regra de conflito

Em caso de conflito entre uma lembrança informal de chat e um documento versionado do repositório, o documento versionado deve ser tratado como referência principal, salvo instrução explícita de revisão.

## 10. Regra de segurança contra perda

Nenhuma decisão técnica relevante deve existir exclusivamente no chat.

Se uma decisão for importante para a continuidade do projeto, ela deve ser convertida em documento e versionada.

## 11. Regra de auditoria

O histórico de commits deve permitir reconstruir:
- o que foi criado;
- quando foi criado;
- quando foi alterado;
- qual versão estava vigente;
- quais decisões foram substituídas;
- qual documento é atualmente aplicável.

## 12. Regra de execução

Esta carta deve ser seguida fielmente em todos os trabalhos futuros relacionados ao projeto Relógio de Água de Ctesíbio.

**Princípio permanente:**
> O chat serve para trabalhar. O repositório serve para preservar.

## 13. Escopo

Esta carta regula o salvamento documental do projeto. Ela não impede a conversa necessária para desenvolver, revisar ou validar conteúdos; determina apenas que o registro oficial e persistente do trabalho deve permanecer no repositório.

## 14. Primeira aplicação

Esta versão registra como patrimônio inicial do projeto os prompts produzidos no trabalho denominado **Prompt clepsidra de Ctesíbio**, incluindo a versão completa e a versão resumida de até 350 caracteres.
